# 迅雷一起看 · 实验版 0.1.0

为两台 Windows 电脑同步播放同一个迅雷云盘视频。两端分别通过迅雷自己的登录会话在线播放，插件仅发送视频标识的 SHA-256、毫秒进度、播放状态、倍速及缓冲标记，不发送账号、Cookie、播放地址或视频内容。

**当前是待实机验收的实验版本。** 已通过模拟播放器和真实本机 WebSocket 的自动化测试；未装入正在运行的迅雷，未做两台真实迅雷或公网联调。不能把模拟测试当作实机成功。当前仅适配本机静态分析的 **25.1.40.1703**，另一端也需此版本。是否允许同一账号同时播放仍待两端实测。

已增加不安装插件的真实进程只读验证：成功连接运行中的迅雷，读到内核版本 **5.2.1.51**，并确认九项播放器接口存在。目前尚未在打开的真实视频上验证进度，详情见 [真实接入记录](真实接入记录.md)。

## 已实现

- 双人随机密钥邀请码；公网连接使用 WSS 加密，任一方可以播放、暂停、拖动和切换常规倍速。
- 使用统一房间时间线、服务端状态序号和时钟偏移估计；拒绝过期操作，抑制远程操作的重复回传。
- 任一方缓冲、状态过期或退出时暂停房间；缓冲恢复后依据用户的播放意图恢复。
- 两端视频标识或时长不一致时暂停房间，且不会向错误视频执行远程跳转。
- 通过迅雷已有的全局播放器实例接入，不构造新播放器、不修改播放器二进制或加密归档。

在线视频仍会有迅雷自身的正常缓冲缓存；插件不会创建完整视频下载任务。音量和字幕各自独立。

## 部署中继

异地观看需要双方可访问的公网中继。此交付包未开通公网服务，也没有内置第三方公共中继。

已有 Node.js 18 或更新运行时的服务器，在本目录运行：

```powershell
npm ci --omit=dev --ignore-scripts
npm run relay
```

默认只监听 `127.0.0.1:8765`。为其配置 HTTPS 反向代理，代理 `/ws` 并支持 WebSocket Upgrade，然后两端使用 `wss://你的中继域名/ws`。`/health` 可检查服务存活。公网域名、TLS 和实际部署需要由服务器管理者配置；不要直接把本机回环地址发给异地伙伴。

如使用容器：

```text
docker build -t thunder-watch-relay .
docker run --rm -p 127.0.0.1:8765:8765 thunder-watch-relay
```

该容器同样放在支持 WebSocket 的 TLS 反向代理后。中继不持久化房间，服务重启后需重建房间；最多两个连接，每个邀请码持有人均能控制该房间。

## 手动安装与启用

从 GitHub 获取的源码不包含 `node_modules`。先安装 Node.js 18 或更新版本，在项目目录安装锁定的依赖：

```powershell
git clone https://github.com/q1f0730/thunder-watch-together.git
cd thunder-watch-together
npm ci --omit=dev --ignore-scripts
```

本地离线交付包已包含 `ws` 依赖，可跳过上述步骤。项目不会在安装依赖时自动安装插件、关闭或启动迅雷。

1. 两端用户各自退出迅雷。如果程序目录需要管理员权限，请由用户打开有相应权限的 PowerShell。
2. 在此插件目录先检查计划：`./Install.ps1`。确认指向自己的迅雷目录。
3. 用户自行执行 `./Install.ps1 -Apply`。脚本只增加 `resources/app/plugins/watch-together/` 目录，并在同级 `config.json` 增加该插件项；保留带时间戳的原配置备份。
4. 用户自行启动迅雷，主窗口右下角应出现“一起看”。若没有出现，先停在此处，按分析文档排查加载入口；不要盲目替换原包。
5. 两人各自打开并开始播放同一个云盘视频。创建者填写公网中继地址，点击“创建房间”，把邀请码私下交给另一人。
6. 另一人在“一起看”面板粘贴邀请码，点击“加入房间”。双方就绪后同步；任何一方都能在原播放器里控制播放和跳转。

退出房间即停止该端同步。连接中断不自动重连，请用户手动重新加入。

## 卸载

用户自行退出迅雷后，执行 `./Install.ps1 -Uninstall` 查看计划，再加 `-Apply` 移除插件配置项。脚本保留插件目录和原配置备份，便于检查；不会递归删除文件，也不会自动启动迅雷。

## 开发验证

```powershell
npm test
npm run probe
```

`probe` 只读本机程序的版本和接口字符串，不打开窗口、不加载原生模块、不读取用户账号资料。它通过也只代表静态匹配。

### 真实进程只读验证

用户自行启动迅雷、打开云盘视频后，在项目目录执行：

```powershell
npm run probe:live
```

此命令通过迅雷已有的本机命名管道，读取播放器版本、当前媒体是否存在，以及三次状态/进度/时长采样。它不安装插件、不重启迅雷、不操控窗口，不读取账号、Cookie、视频标题或播放地址。验证器拒绝发送播放、暂停和跳转命令；确认这些接口“存在”不等于执行过控制测试。

退出码：`0` 表示真实媒体进度读取通过，`2` 表示已连接但仍需打开视频或继续检查，`1` 表示连接或读取失败。插件面板的实际加载与控制行为仍需单独验收。

## 当前限制

- 尚未验证真实加载环境中 `global.AplayerStackImplInstance` 的可见性、各方法返回形态及回调时序。若不可见，面板会显示等待初始化，不会创建新原生实例。
- 同一视频优先用 GCID 比较；缺失时用云盘文件 ID。不同账号中独立保存的文件若没有相同 GCID，可能被保守地判为不同视频。
- 开始订阅前已经发生的缓冲状态可能无法立即获知；必须通过实机验收确认事件初始值行为。
- 250 毫秒轮询，约 1.2 秒偏差触发跳转纠偏。自动纠偏后的 1 秒用于等待播放器响应，期间快速连续手动操作可能被重新对齐。未承诺帧级同步。
- 同时发生的操作按服务端接收顺序处理；过期操作会被最新状态覆盖，用户可重试。
- 插件只控制已打开的视频，不自动打开云盘文件、不自动换集；需要双方手动打开同一集。
- 迅雷升级可能改变内部接口或加载机制；遇到非适配版本会禁用连接。
